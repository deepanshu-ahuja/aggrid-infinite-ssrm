How to read the exceptions

  • Focused is intentional for deterministic race/state-machine behavior such as request freshness, cancellation and safe in-flight acknowledgement.
  • N/A means the capability is not applicable or is not enabled on that current demo route; it is not automatically a test gap.
  • The browser routes are tested as configured today. We do not create fake E2E-only routes just to turn every cell green.
  • Import has focused backend validation/atomicity tests, focused frontend workflow tests, one real Preview/Apply/data-refresh scenario per row model, and one real interaction-mode transition scenario per row model.
  • Mutation-path browser coverage exercises Row Save, Save Selected and selected Change Status interaction-mode transitions across all three row models; Client and SSRM also verify an active indeterminate native header remains primary-colored when restricted rows are present.
  • Backend stale-write/version concurrency remains a separate deferred contract and is not represented as implemented coverage here.

Maintenance rule: update the relevant row when coverage changes, and never label a browser scenario “Covered” until the corresponding test has actually passed CI.
